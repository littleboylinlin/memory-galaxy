# Memory Galaxy 0.6.0 验收记录

基线为 0.5.0 的 `main` 提交 `366405231961bd7b3f9364bcaa9733244196d74d`。

## 架构审计

| 范围             | 0.5.0 实现                                            | 0.6.0 桌面设计                                       |
| ---------------- | ----------------------------------------------------- | ---------------------------------------------------- |
| 前端             | 原生 JavaScript、Canvas 和 Worker，应用资源随站点提供 | 同一套前端随应用打包，由隔离的 Electron 渲染进程使用 |
| 图谱、关系与历史 | 同源 IndexedDB 中的工作区，兼容早期浏览器本机缓存     | SQLite 工作区记录，沿用原有备份结构及校验            |
| 主题包           | 独立 IndexedDB，含配置、差异基线和删除标记            | SQLite 主题包记录，沿用稳定 ID、修订号与指纹         |
| 回顾与收藏       | 独立 IndexedDB，以稳定 ID 保存收藏、跳过与回顾        | SQLite 回顾记录，沿用内容指纹和操作规则              |
| 导入导出         | MGP 1.0 兼容与 1.1，独立的主题包 JSON 和工作区备份    | 沿用三种格式，新增含全部资料的带校验便携备份         |

Electron 将 Chromium 和 Node.js 随安装包分发，可复用现有模块、Canvas 和 Worker。Tauri 可以随包嵌入离线 WebView2 安装器，运行时涉及 WebView2 版本，桌面存储层也需另一套工具链。本轮采用 Electron 和 Node 内置 SQLite，换取渲染环境一致和原生事务存储。资料库 IPC 仅供应用本身的顶层页面调用。原生进程负责文件选择、备份写入、冲突确认和事务提交。

参考 [Electron 文档](https://www.electronjs.org/docs/latest) · [Tauri 离线安装器](https://v2.tauri.app/distribute/windows-installer/) · [SQLite 原子事务](https://www.sqlite.org/atomiccommit.html)。

## Windows 与发布验收

Windows 工作流在 `windows-2025` 上构建安装包、执行 NSIS 安装并启动实际安装的程序。测试对安装器与应用进程限制外部网络连接，使用合成资料验证图谱导入、收藏与回顾、主题包、改用自选目录、正常关闭、强制终止后重开、备份及另一独立资料库恢复。测试以预设路径替代系统选择器的人工点击，资料库与文件写入走实际 Windows 运行时。

首轮 Windows 构建完成了安装、离线启动、导入、回顾、主题包和目录切换。测试将临时目录的短路径与界面显示的完整路径直接比较，导致断言中断。测试现以规范化路径比较。第二轮通过正常关闭与重启，结束主进程后立即重启未完成。强制退出场景改用 Windows 进程树终止，应用对短暂的配置目录锁占用增加一次重试。后续各项以对应提交的工作流结果为准。

正式发布作业使用合并提交的 Windows 安装包。Windows 安装测试和 Pages 线上校验均成功后，发布作业核对 SHA-256 并上传安装包。
