# Memory Galaxy 0.8.1 验收

基线为正式发布的 `v0.8.0`（`295c4f678e08bb4523ccae8ce1fd3e63b6ba102b`）。重新下载 Linux x64 AppImage 并核对 SHA-256，解包后比对加密、资料库、备份和桌面入口代码。此前外部 AppImage 试用反馈单独记录，本页测试结果来自本轮执行。

## 修复与保护边界

- 加密备份选择后，解锁前会重新核对文件的 SHA-256。即便替换文件能用同一密码解锁，也需要重新选择。确认阶段使用已经核对并预览的内容。
- 恢复页标明目标资料库的加密状态。将加密备份写入明文库需要明确确认。MGP、主题包和普通工作区备份使用明文格式，导出入口会提示。
- 新建加密副本只加密新目录，原资料库及已有导出保持原样。密码长度与 UTF-8 字节上限在打开保存对话框前校验。界面说明忘记密码后只能从仍可打开的资料库或备份恢复。
- 明文 SQLite、加密 SQLite、MGP、主题包和备份文件的格式延续旧版。加密沿用 scrypt、随机 16 字节盐、AES-256-GCM、随机 12 字节 nonce 和 16 字节认证标签。密钥分开用于记录、ID 和备份。解密通过认证后才解析资料。
- 加密备份认证覆盖整份文件。加密 SQLite 认证单条记录并绑定其类别和 ID。具备磁盘写权限的人仍可删除文件或回退整个资料库。文件系统同步和进程终止测试无法验证实体断电与设备缓存。

## 加密存储规模测试

本轮在 Linux x64 容器运行，内核 6.18.57，Intel Xeon Platinum 8573C，Node 24.22.1。每组使用虚构的记忆、关系和一份历史快照，在独立进程运行。连续 8 次提交取中位数。备份列含序列化、加密、写入及同步，读取列含读盘、密码派生、解密和内容校验。峰值 RSS 仅计测试主进程。

| 记忆 / 关系     | 备份 MiB | 保存中位 ms | 加密写出 ms | 读入解密 ms | 恢复事务 ms | 峰值 RSS MiB |
| --------------- | -------: | ----------: | ----------: | ----------: | ----------: | -----------: |
| 1,000 / 1,000   |     0.45 |       15.34 |       24.92 |      620.23 |       14.82 |       225.68 |
| 10,000 / 10,000 |     4.60 |      158.25 |      183.71 |      525.05 |      157.92 |       501.41 |
| 50,000 / 50,000 |    23.35 |    1,028.46 |    1,142.07 |    1,444.76 |      843.70 |     1,323.75 |
| 10,000 / 80,000 |    19.79 |      900.21 |      991.83 |    1,390.10 |      800.53 |     1,306.70 |

每组核对了恢复后的完整状态。强制终止持有 SQLite 回滚日志的写入进程后，最后已提交内容与版本一致。另强制终止加密备份的暂存写入，正式文件名未出现，已有备份仍可解密。2 MiB 隔离文件系统的 `ENOSPC` 用例验证了已提交的加密 SQLite 数据和原加密备份均可读回。

使用 `npm run benchmark:encryption` 复跑。脚本也可接收基线工作树路径。表中为候选工作树实测，数值受缓存和机器负载影响。大图用例峰值超过 1 GiB。

## 跨平台验收范围

- Windows 在同一默认资料库依次运行正式 0.7.0、0.8.0 安装器及候选安装器，核对升级后的内容、关系、回顾和主题包基线，并在卸载后校验数据库。
- Apple Silicon、Intel macOS DMG 与 Linux x64 AppImage、deb 的原生包验收沿用隔离外网的流程。Linux AppImage 使用 extract-and-run。
- Windows、两个 macOS 架构和两份 Linux 包使用同一组合成的 v0.8.0 加密 SQLite 与加密备份样本。样本由 SHA-256 校验通过的 v0.8.0 Linux AppImage 内模块生成，涵盖稳定 ID、关系、历史、回顾和主题包。
- 原生文件选择器由测试提供选择结果，随后的读取、验证、密码解锁和恢复由安装包中的应用执行。三平台实体设备、实体断电、真实系统文件选择器点选、Gatekeeper 首次打开及 AppImage FUSE 挂载仍需实测。Windows 安装包无发行者签名，macOS 仅有 ad-hoc 签名。

发行包执行结果以正式发布对应提交的 CI 为准。
