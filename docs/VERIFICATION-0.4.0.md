# Memory Galaxy 0.4.0：回顾与体检验证范围

基于 main `e06752718ab1c5c1bb8e8bdf550ef178ccc2c3b0`（0.3.5）增量开发。新增功能版本为 0.4.0，MGP 仍为 1.1，兼容 1.0；原有完整工作区备份仍使用 `memory-galaxy/backup/1`。

## 功能和规则

回顾页复用现有查找、类型和状态筛选、分页、按钮样式及记忆详情入口。默认按记录提供的 `updated_at` 推荐至少 30 天未更新的记忆，可调整至 90 或 180 天；不推荐已过时状态。时间缺失、无效或晚于本机时钟时不推断新旧，可通过“全部记忆”或“未提供可用时间”主动查看。相同时间按稳定 ID 排序，没有语义重要性评分。

每张卡片展示原标题、正文摘录、完整稳定 ID、来源声明与引用、实际筛选原因和已有关系数。关系只取当前图谱中的原始记录，保留类型、方向、依据、推测/明确/规则声明、来源与引用；其余关系可在原有详情中分页查看。关系声明不等于独立事实核验，空间位置与同名均不会生成关系。

收藏、跳过 7 天、标记已回顾及重新待回顾只写独立的 `memory-galaxy-review` 浏览器数据库，不写入图谱、快照、操作时间线或原始导出。以稳定 ID 识别记忆；不同记忆不能复用 ID。收藏保留在同一 ID 上，已回顾与跳过还记录当前记忆、相关来源声明及实际关联记录的 SHA-256 指纹。当前版本已回顾后暂缓 30 天，内容、来源或已有关系变化后重新参与回顾；不补造此前的回顾历史。

回顾记录只含 ID、状态、实际本机标记时间及版本指纹，不复制原文。每次操作在读写事务中读取最新记录，只更新对应状态，事务完成后才反馈成功；失败保留原状态并提供重试。保存期间暂停重复操作并注册刷新保护。跨标签页按记录合并不同状态字段，广播不可用时可手动刷新回顾。损坏记录拒绝覆盖，体检与原有工作区继续可用。

原有 MGP JSON / JSONL 及完整工作区备份不包含个人回顾状态。回顾页有单独的确认清除入口；清除工作区缓存会保留回顾状态并明确提示。清理浏览器站点数据会丢失这些个人状态，本轮没有增加其跨设备同步或导入导出。

体检在本地 Worker 检查整个当前图谱，不受工具栏筛选影响，不检查历史快照和删除墓碑。四项可以重叠，不合计为“错误总数”或健康评分：

| 检查             | 依据和限制                                                                                                                                      |
| ---------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| 疑似重复         | 分别按同类型标题与非空正文分组，统一大小写、兼容字符与连续空白；只提供字面线索，同名不等于同一记忆；分组保留全部 ID，成员分页，避免枚举两两组合 |
| 孤立节点         | 只根据实际边判断是否关联其他记忆；自关联单列解释，孤立本身不一定异常，不建议凭相似度补关系                                                      |
| 来源或追溯不完整 | 区分没有可用声明/只有工作区占位来源，与有声明但没有原文引用；接受已有 provenance 引用和手动来源声明，不补造出处                                 |
| 待核实旧记录     | 未知、推测或有争议状态且提供的更新时间距今至少 90 天，可改 30/180；已确认、已过时、无可用时间及未来时间不计入；不声称存在或知道最后确认时间     |

检查结果只有查看与核对入口，复用现有记忆详情；不执行合并、删除、修改或状态确认。分析取消、失败、超时或图谱变化后不应用旧结果。新标签、筛选和页码使用原有 sessionStorage 临时状态机制，不把记忆正文写入临时界面状态。

## 测试证据与结果入口

本地单元、协议、生命周期、存储状态规则及构建相关测试共 **172 项通过、0 失败、0 跳过**，新增 19 项。针对旧时间与未来时间、时间阈值、到期边界、指纹变化、同名 ID、只读分析、来源引用、损坏状态及 10,000 条重复组成员进行检查。格式、源码绑定、工作流 YAML、构建及 32 个公开产物文件的完整性检查通过。

浏览器套件新增 **13 项场景**，每项目由 70 项增至 83 项，四个现有浏览器项目共 332 项。新增场景检查原图谱与保存版本不变、收藏/跳过/已回顾刷新恢复、事务完成前反馈与刷新保护、配额失败重试、两个标签页分别操作同一 ID、关系变化、损坏记录、明确清除、Worker 失败及过期结果、10,000 条分组与延迟成员分页、三来源 402 条记忆 / 2,028 条关系 JSONL 的原样导出，以及 390×844、844×390、1365×900 视口与不可信文本。最终功能提交 `f98e5be` 的 PR 回归与合并提交 `08d9e6f` 的 main 回归均已实际执行：桌面 Chromium、Firefox、手机 Chromium、WebKit 各 **83 项通过**，合计 **332 项通过、0 失败、0 跳过**。Node.js 22 与 24 各 **172 项通过、0 失败、0 跳过**。

本地 Playwright 运行在 Chromium 启动阶段因 `socket() failed: Operation not permitted` 失败 1 项，另 12 项未执行，未将其计为功能验证通过。完整矩阵交由仓库原有 GitHub Actions 执行；独立浏览器另做手工导入、回顾、收藏、跳过、已回顾、刷新和体检核对。使用同源页面与 Worker，浏览器用例检查请求没有离开项目来源，不上传私人记忆，不增加在线模型或运行时第三方依赖。

合并后沿用既有 Pages 流程：检查 Node.js 22 / 24、全部四组浏览器、构建产物、线上 revision 与公开文件 SHA-256、桌面和手机尺寸 Chromium 共 6 项部署冒烟。

## 无法验证及边界

手机竖横屏均为浏览器视口和触摸模拟，不是真实 iPhone / Android 硬件实测。没有本轮私人记忆或真实 AI 导出文件；测试数据全部为虚构数据。未验证实体设备键盘、动态地址栏、协议上限的交互帧率、系统断电或浏览器崩溃时的磁盘行为。

推荐与体检仅使用明确规则与已有声明，不进行语义理解，也不能证明数据重复、来源真实、记忆正确或知识完整。个人状态依赖此浏览器和稳定 ID，原有备份不包含它们。按主题打包给 AI 不在本轮范围。保留旧验证记录、许可证与开发历史；开发分支由维护者自行删除。
