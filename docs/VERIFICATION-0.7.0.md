# Memory Galaxy 0.7.0 验收记录

基线是正式标签 `v0.6.0` 对应的 `024d97166c88fdc861d994fe41a3dc3f85ce7873`。同一套 Electron 前端和内置 SQLite 用于五份发行包。0.6.0 的 Windows 应用标识、安装方式、默认配置目录与数据格式均用于本轮升级校验。

| CI 环境                 | 发行包安装和移除方式                                                                  | 离线验收范围                                                                                                          |
| ----------------------- | ------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| Windows Server 2025 x64 | 在同一目录依次安装校验过的 0.6.0 NSIS 和 0.7.0 NSIS，再运行卸载器                     | 对安装器和应用阻止外部网络。比对升级前后的默认资料库、图谱、回顾和主题包基线，卸载前后比对 SQLite 文件哈希。          |
| macOS 15 Apple Silicon  | 挂载 arm64 DMG，复制应用到测试目录，再移除应用包                                      | 核对 Mach-O 架构与 ad-hoc 签名，在隔离外部网络连接的条件下启动，检查默认资料库在移除后保留。                          |
| macOS 15 Intel          | 挂载 x64 DMG，复制应用到测试目录，再移除应用包                                        | 与 Apple Silicon 使用相同的步骤，运行的是 Intel 发行包。                                                              |
| Ubuntu 22.04 x64        | 离线安装和清除 deb，运行发行版 AppImage 的 extract-and-run 模式，再移除 AppImage 文件 | 在只启用回环接口的网络命名空间中验证两个发行包，核对 deb 与 AppImage 共用同一默认资料库，移除后核对 SQLite 文件哈希。 |

每个发行包运行相同的原生应用验收。验证从打包后的应用加载资源与 SQLite，使用非 ASCII 自选路径，写入记忆和关系、收藏、回顾与主题包，正常关闭和强制终止后重启，完整备份，在独立资料库中取消和确认恢复。检查系统文件选择器的父窗口、选择类型、JSON 过滤器和保存路径参数，测试传入选择结果后由原生应用完成文件读写。

浏览器回归覆盖桌面和移动 Chromium、Firefox 与 WebKit。Pages 构建和上线后校验独立运行，发布作业在三平台验收和 Pages 线上检查全部成功后核对五份发行包的提交与 SHA-256。

首轮主分支复验在 macOS 的联网对照步骤收到 HTTP 403。该步骤改为用传输是否连通判断外网，避免把服务端返回的状态误判为网络故障。

验收使用 GitHub 托管环境。Windows 10/11 实机、实体 Mac、Linux 桌面实机、系统文件选择器的人工点选、下载后 Gatekeeper 的交互流程、AppImage 的 FUSE 挂载及两台实体设备之间的迁移属于独立验收范围。macOS 发行包只使用 ad-hoc 签名。每个版本的实际通过记录以 Release 链接的对应提交 CI 为准。
